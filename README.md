# Interview Prep — AI-Assisted Coding Sessions

A structured preparation environment for AI-assisted technical interviews.
Built to demonstrate not just what gets built in a session, but how problems
are decomposed, how AI tooling gets directed, and how thinking evolves across
practice runs.

The repo is intentionally public. The design process, practice sessions, and
session logs are all visible. That transparency is the point.

---

## How It Works

Each practice session follows a fixed sequence:

1. **Decompose** — write initial notes and approach in `plan/` before touching any code
2. **Plan** — direct Claude Code to generate a `WORKORDER` and approve it before execution
3. **Build** — execute the WORKORDER in chunks, staying in scope
4. **Document** — run scripts to compile the session log and AI review after the session

The templates are pre-configured environments that get copied into a new session
folder for each practice run. Templates stay clean — sessions are where the work happens.

For full design detail and the reasoning behind every decision, see `PROJECT_SPEC.md`.

## Repo Structure

```
templates/      — reusable Python and TypeScript environments
sessions/       — documented practice runs
scripts/        — session management and review tooling
docs/           — templates and reference documents
memory/         — root session context
```

## Quick Reference

**Start a new session:**
```bash
./scripts/gen_session.sh python
./scripts/gen_session.sh typescript
```

**Compile the session log after a session:**
```bash
./scripts/gen_session_log.sh prep_001_python
```

**Run the AI review:**
```bash
./scripts/gen_session_review.sh prep_001_python
```

**Session folder structure:**
```
sessions/prep_001_python/
├── session_log.md      — your reflection (fill in after session)
├── review.md           — AI review output (generated by script)
├── memory/MEMORY.md    — Claude Code session log (auto-written at END SESSION)
├── plan/               — scratch notes, plan, and WORKORDER from the session
└── [code files]        — what was built
```

## The Session Log

After each practice run, fill in `session_log.md`:

- What was your initial read on the problem?
- What is the why — what questions should you have asked?
- What approach did you choose and why?
- How did the session go — where did you gain ground, where did you lose time?
- What would you do next with more time?
- What would you harden before this went anywhere real?
- Score yourself honestly

The session log is your voice. The `memory/MEMORY.md` is Claude Code's output.
Together they tell the full story of the session.

---

## The Review

After completing the session log, run `gen_session_review.sh`. It assembles
the session artifacts, pipes them to Claude, and compiles a structured review
covering six dimensions:

- Problem decomposition
- Question quality
- AI direction
- Scope judgment
- Production thinking
- Communication clarity

Plus perspectives from a VP of Engineering lens and a Software Architect lens,
each with an explicit would_hire verdict.

The review is a feedback tool, not a code review. It evaluates thinking and
judgment, not syntax or whether the solution is fully working.
